# 지난 실패 기록

AI가 비슷한 일을 시작할 때와 관련 파일을 고치기 직전에, `tools/lessons/find.js`가 여기서 맞는 기록을 찾아 AI 앞에 띄웁니다. Claude는 훅으로 자동으로 띄우고, Codex는 `AGENTS.md`에 적힌 대로 직접 실행합니다.

- 새 실패는 AI가 아래 모양으로 덧붙이고 보고의 "한 일"에 적습니다. 틀린 기록은 사용자가 지우라고 하면 지웁니다.
- 항목 모양: `## 제목` 다음 줄부터 `- 낱말:`, `- 파일:`, `- 있었던 일:`, `- 원인:`, `- 이렇게 한다:`.
- 낱말: 사용자 말에 이 낱말이 있으면 뜹니다. 쉼표로 나누고, `+`로 이으면 모두 들어 있어야 맞습니다.
- 파일: 이 파일을 고치기 직전에 뜹니다. 경로의 끝과 견주고, `*`는 아무 글자입니다.
- 직접 찾아보기: `node tools/lessons/find.js "할 일"` 또는 `node tools/lessons/find.js --file <경로>`.

- 원인: 검사가 실패하면 통과시키는 쪽으로 먼저 움직였다.
- 이렇게 한다: 시험을 고치기 전에 코드와 시험 가운데 무엇이 틀렸는지 근거를 먼저 말한다.

- 원인: 새 행동이 승패에 미치는 영향을 재지 않고 넣었다.

## 같은 지시를 세 번 되풀이해 맡김
- 낱말: 세 번, 3번, 되풀이, 반복+지시, 반복+비교
- 있었던 일: 2026-11-16, 사용자는 "세 번 비교"로 서로 다른 내용의 결과 셋을 바랐는데, 다른 AI가 같은 작업을 같은 지시로 세 번 맡겼다. 뒤로 갈수록 결과가 줄고 이상해졌다. 작업 폴더를 막지 않아 뒤의 작업자가 앞의 결과를 봤을 수 있다(확인 못 함).
- 원인: "세 번"을 같은 일의 반복으로 좁게 읽었고, 되풀이한 지시가 "앞 결과가 틀렸다"로 읽힐 수 있음을 생각하지 않았다.
- 이렇게 한다: 여러 번 하라는 말이 같은 일의 반복인지 서로 다른 결과 여럿인지 확인한다. 다시 맡길 때는 무엇이 달라야 하는지 적고, 같은 조건을 되풀이해야 하는 실험이면 작업자와 폴더를 서로 못 보게 나눈다.

## 전략을 설명 창으로 보여 주려 함
- 낱말: 전략, 명확하게+게임, 알기 쉽게+게임, 전략판
- 있었던 일: 2026-11-16, 사용자가 "전략적인 요소를 명확하게 해서 서로 재미있게 즐길 수 있게"라고 하자, 이기는 길과 맞수를 적은 "전략판" 창을 범위표와 시안까지 만들었다. 사용자는 "이걸 보여줄 이유가 없습니다. 게임 플레이로 알아야 하며 그것이 어려우면 안됩니다"라고 했다.
- 원인: "명확하게"를 화면에 설명을 더하는 일로 읽었다.
- 이렇게 한다: 규칙이나 전략을 알게 하라는 요청이면, 먼저 플레이 안에서 드러나게 할 방법(NPC의 말과 반응, 행동의 결과, 이야기의 변화, 할 수 있는 행동)을 찾는다. 설명 창은 사용자가 따로 원할 때만 만든다.
